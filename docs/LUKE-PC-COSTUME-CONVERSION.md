# Luke Cage PC costume conversion

Validated 2026-10-18. This is a private-asset conversion recipe, not an asset redistribution.
The installed game contains default 25101 plus alternates 90000-90003, made from
MUA1 PC actors 15701-15704 respectively. The existing herostat already had those slots.

## Reproduce the models

Use Blender 4.5.8 LTS and KaikoClanworth1/igb-blender at
`a509dcc69438b53bdfe8daeaa793db68fec960b0`. Keep the checkout, temporary files and
output under this repository's `.local`. Apply
`tools/patches/igb-blender-wii-rgb5a3.patch` to that checkout (already applied in
`.local/luke-pc-20261018/igb-blender-reference`).

The patch adds a Wii RGB5A3 diffuse export option to the add-on's existing complete
skin graph builder. It writes big-endian 4x4 tiled pixels with image format 21 and
order 103, matching the native Alchemy Wii image metadata. Its color, alpha and
multi-tile vectors were checked. The upstream GameCube CMPR option produced
rainbow noise in this game and is not used. V6 DXT and V8 output failed to load in
Alchemy 5, so those candidates were rejected as well.

Run Blender in background/factory-startup mode with `--disable-autoexec`,
`--python-exit-code 1`, and `--python tools/export_luke_pc_costumes_blender.py`.
After Blender's `--` delimiter, supply:

- `--addon .local/luke-pc-20261018/igb-blender-reference`
- `--actors "C:/Games/Marvel Ultimate Alliance/actors"` (authorized read-only donor)
- `--output .local/luke-pc-20261018/reproduced`

Before launching, point TEMP and TMP at the task's `.local/.../temp`,
BLENDER_USER_RESOURCES at `.local/.../blender-user`, and set
PYTHONDONTWRITEBYTECODE=1. No add-on installation, global settings or saved Blender
preferences are needed. The actor import/export pipeline preserves the skinned
mesh, materials, bone palette and bind relationships as one graph. The output has
42 armature bones and 32 used palette entries. All vertices have normalized weights.
Diffuse textures are 256x256; normal, specular and gloss maps are omitted.

The four output sizes are 342461, 461801, 342489 and 370749 bytes. Re-running the
retained entry point produced exactly the same four byte streams as the tested set.
This is scoped to these four models; it is not a general cross-game converter yet.

## Packaging and validation

Only `actors/90000.igb` through `actors/90003.igb` were replaced inside their
`packages/generated/characters/lukecage_<id>.fb` and `_nc.fb` packages. The `_c`
packages and every other FB member remain byte-identical. The installed WAD was
built from the installed baseline, not from the test WAD. All other ZIP entry
payloads, herostat, executable and real saves were verified unchanged.

The private fixture copies a profile and routes map startup to the native Bravo
team-selection menu. Selection and X cycling use process-local port-0 input;
read-only focus queries guide navigation. No host input or direct menu/hero state
writes. All four models were inspected in native game captures; two complete
cycles wrapped to default, then slot 3 entered Stormcastle with the visible party
and environment. Exit code 0. No invalid-read/fatal error in the successful run.
This does not establish full campaign coverage, all animations, audio (Null backend),
combat FPS, or four-controller acceptance.

Evidence: `evidence/windows-20261018/LUKE-PC-COSTUMES.json`.
Private captures/logs: `.local/luke-pc-20261018/run-blender-rgb5a3`.
Compact rollback of the eight original FB packages:
`.local/luke-pc-20261018/rollback-packages.zip`.
The local `stage_verified.py` retains the exact member-by-member packaging checks.
No proprietary models, WAD, extracted data, or captures belong in Git.

Alchemy 5 was found via the MarvelMods Alchemy tutorial
(https://marvelmods.com/forum/index.php?topic=11158.0) and unpacked locally without
running its setup scripts. It supplied reference image metadata; the passing models
were generated by the patched Blender add-on, not by an Alchemy batch conversion.
