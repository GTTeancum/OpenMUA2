Native REL cache-invalidation scan fix:

- Root cause found for the first REL stall: `OnICacheInvalidate()` translated
  every invalidated cache-line address through `ResolveNativeAddress()`. With
  REL metadata present, an arbitrary data/cache address outside known code
  could fall through into `RefreshRelSections()`, scanning guest RAM for the
  REL header on each `dcbf` in the early cache-flush loop.
- `ResolveNativeAddress()` now has an `allow_refresh` parameter.
- Dispatch/PC resolution still allows REL layout discovery.
- I-cache invalidation uses `allow_refresh=false` so data/cache invalidations
  do not trigger full REL-header scans.
